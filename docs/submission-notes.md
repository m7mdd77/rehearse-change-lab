Rehearse rehearses an actual database deletion before it can run. DeepSeek v4 Flash turns a retention request into a typed filter or asks for clarification. It cannot write SQL, approve changes or invent predictions. The exact deletion and foreign-key cascades run on a copy of the visitor's persistent SQLite workspace.

Review the before/after counts, affected tickets/customers and recovery boundary. An eight-ticket batch is blocked. Narrow to resolved Delivery tickets before 2026-09-01: three tickets, six notes and three attachment metadata rows are removed. Execute the reviewed preview, inspect the changed Records view, then restore the original rows.

Failure: arm “Explore an unexpected side effect” after simulation. The actual adapter also attempts to change a customer preference. Comparing actual and predicted full-row diffs inside the transaction catches it and rolls back every domain change. A containment receipt persists. Stale/expired previews and conflicting restores are refused.

These are real SQL/API changes to fictional disposable data, with no production database or physical file deletion. The public service uses Worker/D1 and an authenticated outbound PC worker; live operations need that PC awake. The provider key stays local. AI tools: OpenAI Codex for implementation/review and genuine DeepSeek for filter interpretation. Unit tests and actual provider evidence are separate.
